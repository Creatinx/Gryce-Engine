# Gryce Engine 项目总览与开发指南

> 本文档面向**新加入的开发者**，帮助快速理解项目整体结构、构建方式、开发约定和关键设计决策。

---

## 1. 项目概述

Gryce Engine 是一个**C++23 游戏引擎**，处于原型阶段。核心架构：

- **渲染**：Vulkan 1.2（默认）/ OpenGL 4.6（兼容）双后端
- **架构**：ECS（Entity-Component-System）+ 场景节点树
- **模块化**：核心拆分为 4 个 DLL，通过**纯 C API**（`extern "C"`）对外服务
- **编辑器**：WPF（C#，.NET Framework 4.8），与核心完全解耦
- **脚本**：GryceSRT（Lua 脚本系统），2D 演示已完整使用

## 4. 核心架构概览

### 4.1 分层架构

```
宿主层（C++ 示例 / C# 编辑器）
    │  C ABI（extern "C"，cdecl，UTF-8 字符串）
    ▼
模块层（4 个 DLL）
    ├── GryceCore.dll      — ECS、场景、组件、反射、资源、动画、音频、渲染抽象
    ├── GryceRenderer.dll  — OpenGL/Vulkan 后端、2D/3D 渲染系统、ImGui
    ├── GrycePlatform.dll  — GLFW 窗口、输入、光标
    └── GrycePhysics.dll   — Jolt 3D / Box2D 2D 物理
    │
    ▼
第三方（GLFW、GLEW、Vulkan、Jolt、Box2D、Assimp、Lua...）
```

### 4.2 模块依赖

```
GryceCore      ← 基础层（无内部依赖）
GrycePlatform  → GryceCore
GryceRenderer  → GryceCore + GrycePlatform + GLFW/GLEW/Vulkan
GrycePhysics   → GryceCore + Jolt/Box2D
```

### 4.3 线程模型

**编辑器模式**：
- UI 线程：60Hz `DispatcherTimer` → `GCore_BeginFrame` → `GCore_EndFrame`
- 渲染线程：垂直同步 → `GRender_BeginFrame` → `GRender_RenderWorld` → `GRender_EndFrame`
- 共享保护：全局递归互斥锁（`GRYCE_API_GUARD`）

**独立模式**（demo）：
- 单主循环驱动窗口/输入/更新/渲染
- `RenderContext` 异步模式内部启动渲染线程

### 4.4 关键数据流

**编辑操作**：
```
Editor → GCommand → GCore_PushCommand → CommandBuffer（双缓冲）
→ GCore_BeginFrame：swap + 消费（≤30/帧）
→ process_command：LOAD_SCENE / CREATE_ENTITY / SET_PROPERTY ...
→ ecs::World / scene::Entity 写入
→ GCore_EndFrame：触发回调 → 编辑器刷新面板
```

**Play Mode**：
```
ECMD_PLAY_MODE → 保存场景 JSON 快照 → world.set_updates_enabled(true)
→ PhysicsSystem / AnimatorSystem / ScriptSystem 每帧驱动

ECMD_STOP_MODE → 反序列化快照 → 替换场景（丢弃播放期改动）
```

## 5. 关键设计决策

### 5.1 C API 是唯一通道
编辑器与核心之间的**唯一通信方式**是纯 C API（`extern "C"`）。任何新增的编辑器功能都应优先以 C API 暴露，避免直接 `#include` 内部头文件。

### 5.2 命令队列 vs 直接 API
- **结构性修改**（创建/销毁实体、改属性、Play Mode）→ 通过 `GCore_PushCommand` 命令下发
- **直接查询类**（枚举实体、读属性）→ 同步调用 `GEntity_*` / `GComponent_*` API

### 5.3 渲染抽象在 Core，实现在 Renderer
渲染的**抽象与管线**（RenderContext、Material、RenderPipeline）位于 GryceCore.dll；
**具体后端**（OpenGL、Vulkan）位于 GryceRenderer.dll。这是为打破循环依赖而做的边界划分。

### 5.4 双场景槽
编辑器支持 2D/3D 场景热切换，`EngineContext` 中维护 `scene_slot_2d` 和 `scene_slot_3d` 两个独立场景，切换时不释放场景内存。

### 5.5 实体句柄
`GEntityHandle` 是 `int` 类型，通过 `EntityHandleMap` 映射到内部 UUID。句柄不能跨场景保存使用——场景加载/新建后句柄表会重建，旧句柄可能失效。

## 6. 开发约定

1. **C API 是 Editor 与 Core 之间的唯一通道**
2. **手动复制链接库必须同步到 CMake**：在 `core/CMakeLists.txt` 中通过 `gryce_copy_dll_to_editor` 添加自动复制规则
3. **公共头文件集中在模块目录**：`core/GryceCore/`、`core/GryceRenderer/` 等
4. **提交信息遵循 Conventional Commits**（`feat:` / `fix:` / `docs:` / `perf:`）
5. **DLL 命名**：Debug 带 `d` 后缀（`GryceCored.dll`），Release 不带
6. **所有字符串按 UTF-8 编码**（路径、实体名、组件名、日志）
7. **所有导出函数受全局递归互斥锁保护**（`GRYCE_API_GUARD()`）
