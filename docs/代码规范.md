# 代码规范（注释约定）

> 本文规定本项目源码的注释风格。适用于本仓库，尤其本仓库所有**新写或重构触及**的代码。
> 历史代码不必逐一改写，但修改过的文件应就地与新风格保持一致。

## 一、语言

- 注释统一使用**中文**（术语、API 名、链接库名可保留英文原样）。
- 除必要的协议声明（如 `__declspec`、`extern "C"`）外，避免用注释夹带杂乱符号。

## 二、文件头注释

每个 `.cpp` / `.h` 顶部用块注释简述文件职责：

```cpp
// ---------------------------------------------------------------------------
// <文件名> — <一句话职责：这个文件做什么、属于哪个模块/系统>
// ---------------------------------------------------------------------------
```

职责描述要能回答「为什么存在这个文件」，避免流水账复述函数名。

## 三、作用域 / 类注释

- **类 / 结构体**：在其声明上方写块注释，说明用途、生命周期约束、线程归属（如
  「仅渲染线程访问」「主线程拥有 GL 上下文」）。
- **公开函数 / 成员**：只说必要信息（前置条件、副作用、返回值约定），不逐行解释显然代码。
- **非显然逻辑**（算法边界、线程安全、Arena/生命周期归属、易错顺序）**必须**注释原因，
  这是本项目最高优先级注释。

## 四、行内注释

- 只对「不看注释难以理解」的代码做行内注释。
- 不写 `// +1` 这类拷贝式冗余注释，不为可读代码逐行加注。

## 五、CMake 与脚本注释

- `CMakeLists.txt`：每个 `add_library` / target 上方写块注释，说明该模块职责与**依赖方向**；
  刻意保留/拆分某领域时，写明原因与阻塞点（参见 `src/CMakeLists.txt` 的范式）。
- 出错点、平台分支（`#ifdef WIN32`、MinGW/MSVC 差异）就近注明原因。

## 六、提交信息

遵循 Conventional Commits：`feat:` / `fix:` / `docs:` / `refactor:` / `perf:` 等。

## 七、检验原则

写完/重构代码后，回读注释：若删掉某句注释代码依然一目了然，那就删掉它。
保留的每一句注释都应当解释「为什么」，而不是「做了什么」。
