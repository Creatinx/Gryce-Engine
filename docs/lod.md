# 自动 LOD：按几何误差反推切换距离

`MeshRenderer` 默认开启自动 LOD：模型导入时生成整条 LOD 链，运行时每帧按
**几何误差在屏幕上占多少像素**选择级别，而不是写死的距离档。

两级粒度：

- **逐物体**（默认，所有模型）：整个物体选一个级别。远处、小物体全靠这个。
- **空间分块**（单个巨模型，>12 万三角形）：把网格切成 2³~6³ 个空间块，每块
  各自选级。只有"逐块加起来明显更省三角形"时才接管（见 §6.3）。

---

## 1. 为什么是"误差 → 距离"，不是"距离 → 级别"

写死的距离档（`40/120/320`）在换分辨率、换 FOV、换模型尺寸时全错：
同一个 40u，在 1080p / 60° 下是"看不出差别"，在 4K / 100° 下是"轮廓明显破损"。

所以这里走反方向：

```
error / (dist * tan(fov/2)) * (height/2)  =  屏幕上占的像素
```

`error` 是每级简化**实测**出来的几何误差（简化时记录，见 §2），把它代入上式
反解出"误差正好占 `lod_pixel_error` 像素"的那个距离，就是该级的切换阈值：

```
dist_k = error_k * (height/2) / (lod_pixel_error * tan(fov/2))
```

于是：

- 分辨率翻倍 → 阈值翻倍，更晚降级（画质守恒）；
- FOV 变大（广角）→ 阈值变大，更晚降级（同样守恒）；
- 模型缩放 2 倍 → 世界误差 2 倍 → 阈值 2 倍，自动跟着走；
- 想要"更省"就抬 `lod_pixel_error`，想要"更准"就压低。

近处永远是 level 0（原始网格）。低模只在"看不出差别"的距离生效。

## 2. LOD 链怎么生成（`assets/mesh_lod.cpp`）

顶点聚类（vertex clustering），不是 QEM 边收缩：

1. 用边长 `cell` 的立方体栅格划分顶点空间，每簇选一个**原始顶点**做代表
   —— 簇内离质量中心最近的那个，而不是重算质心。保留原始属性（法线 / UV /
   切线 / 顶点色）就不会凭空造出 UV 接缝（合成新顶点会让采样坐标落在两个
   texel 之间，表现为纹理拉伸）。
2. 三角形三个顶点映射到簇后若有重复则丢弃（退化成线/点，光栅化不出像素）。
3. `cell` 由目标三角数二分搜索（6 次迭代，三角数 ~ 1/cell²，用几何中点收敛快）。
4. 每轮记录"簇内顶点到代表顶点的最大位移"，就是这一级引入的误差上界；
   累加成 `cumulative_error`（三角不等式，保守）。

**为什么不用 QEM**：摄影测量 / CAD 网格经常是非流形、非封闭、带大量孤立三角形的
三角汤。边收缩需要可靠的半边拓扑与合法性判定，1.4M 三角形的优先队列要几十秒。
聚类是 O(n) 两次扫描，实测 1.46M 三角形出 3 级共 ~0.2s，且**只删三角形、不移动
连通关系**，永远不会产生破面。

实测（主 demo，1.46M 三角形）：

| 级别 | 三角数 | 本击误差 | 累计误差 | 1080p/60°/2px 下的切换距离 |
|------|--------|----------|----------|---------------------------|
| L0 | 469451 | — | 0 | — |
| L1 | 216216 | 0.2094 | 0.2094 | ≥ 97.9u |
| L2 | 113225 | 0.2446 | 0.4541 | ≥ 212.4u |
| L3 | 59328 | 0.3677 | 0.8217 | ≥ 384.3u |

每一级约减半，累计误差每级递增（因为是在上一级的代表顶点上再聚类）。

## 3. 运行时选择（`components/mesh_renderer.cpp::update_lod`）

```
dist = 到包围球最近点的距离，下限取 0.5 × 到球心距离
```

- **为什么用最近点**：50u 级别的建筑贴近拍摄时，到球心与到最近点差一个半径，
  按球心算会把近景也判成远景（本该 L0 的立面被降到 L2，一眼就看出糊）。
- **为什么要有下限**：整片城市 / 地形这种"把相机包在包围球里"的巨模型，
  最近点距离恒为 0 → LOD 永久失效，`lod_pixel_error` 怎么调都没反应。
  下限取"到球心距离的一半"：越靠近球心（真的站在模型内部）越保守保持高模；
  只是被包围盒包住、看的其实是远处那片表面时，允许按真实距离降级。

**滞回带 8%**：阈值上下 8% 内不切换，抑制"相机在边界轻推一下就来回荡"。
强制级别（`GRYCE_FORCE_LOD`）跳过滞回 —— 它本来就不是边界行为。

**上传是异步的**：切级只投递一条"建 mesh + 上传"命令，命令在渲染线程执行。
未就绪时 `draw_mesh_handle()` 回退到当前最高分辨率的已就绪级别（宁可多画两帧
高模，也不要在切换的那一帧什么都不画）。

**所有绘制通道必须用同一个级别**：主 pass、阴影 pass、法线预通道都用
`draw_mesh_handle()`。预通道如果写 L0 的深度、主通道画 L2，深度与几何就不是
同一张表面（细碎三角形在预通道挡住的像素在主通道被判成遮挡），表现为边缘闪烁
和破洞；顺带还白付一遍高模几何。

**包围球用 L0**：视锥剔除与遮挡剔除判据固定用 `gpu_mesh_handle()`（原始网格）
的包围球，切换 LOD 时剔除判据不抖动。

## 4. 开关与调参

| 手段 | 作用 |
|------|------|
| `MeshRenderer::lod_enabled = false` | 单物体关闭（永久画 L0） |
| `lod_pixel_error`（默认 2.0） | 允许的屏幕误差像素。**这是主要画质/性能旋钮** |
| `lod_bias`（默认 1.0） | 阈值缩放。>1 更晚切低模（保画质），<1 更早切（保性能） |
| `lod_distances`（默认空） | 非空时改用显式世界单位阈值，硬性区间，忽略误差推导 |
| `GRYCE_NO_LOD=1` | 全局关闭，所有物体画 L0（对照用） |
| `GRYCE_FORCE_LOD=k` | 强制所有物体用第 k 级（A/B 截图用） |
| `GRYCE_LOD_PIXEL_ERROR=x` | 覆盖 `lod_pixel_error` 默认值（扫灵敏度用） |
| `GRYCE_LOD_DEBUG=1` | 打印每次选择的距离/半径/各级阈值/结果（前 12 次） |
| `GRYCE_NO_CHUNK_LOD=1` | 只关空间分块 LOD，保留逐物体（A/B 对照） |
| `GRYCE_CHUNK_LOD_MIN_TRIS=N` | 分块门槛（默认 120000；低于它的子网格不做分块） |
| `GRYCE_CHUNK_NO_PIN=1` | 不钉分块边界顶点（验证裂缝来源、量钉顶点的代价） |
| `GRYCE_CHUNK_PIN_STATS=1` | 打印被钉住的顶点占比 |

场景文件里可以直接写：

```json
{ "mesh_path": "res:/models/x.fbx",
  "lod_pixel_error": 4.0,
  "lod_distances": [40, 120, 320] }
```

## 5. 实测

### 5.1 各级的画质与成本（主 demo，相机 [0,34,46]，1080p，MSAA 4x）

用 `GRYCE_LOD_PIXEL_ERROR` 让三个子网格整体落到同一级，同会话交替跑两轮取中位
（`--no-debug-ui --no-fps`，见 performance.md 的"笔记本上必须交替 A/B"）。

| 配置 | 三角形 | 像素平均 \|Δ\| vs L0 | >2 像素占比 | GPU 合计 | scene | vs L0 |
|------|--------|-----------------------|-------------|----------|-------|-------|
| L0（`B=2`，默认） | 1,457,686 | — | — | 8.00ms | 6.97ms | — |
| L1（`B=10`） | 738,326 (-49%) | 2.81 | 20.9% | 6.60ms | 5.73ms | **-17.5%** |
| L2（`B=20`） | 361,430 (-75%) | 4.35 | 30.0% | 4.80ms | 4.09ms | **-40.0%** |
| L3（`B=40`） | 186,194 (-87%) | 5.87 | 36.8% | 4.17ms | 3.49ms | **-47.9%** |

L3 只剩 12.7% 的三角形，画面仍然没有破面（聚类只删三角形、不移动连通关系），
远景轮廓与近景立面都可接受；差异集中在屋顶瓦片/栏杆这类高频细节上。

### 5.2 误差预算 → 实际级别（本 demo 相机）

`center_dist=47.5u`、`radius=62.4u` → `dist = max(-14.9, 23.75) = 23.75u`，
于是各级在该距离上"误差占几个像素"决定是否降级：

| `lod_pixel_error` | 实际级别 | GPU 合计 |
|---|---|---|
| 2（默认） | L0 | 8.00ms |
| 8 | 只有误差最小的子网格 1 切 L1 | 91.9 vs 92.1 均值 |
| 10 | 全部 L1 | 6.60ms（-17.5%） |
| 20 | 全部 L2 | 4.80ms（-40.0%） |
| 40 | 全部 L3 | 4.17ms（-47.9%） |

默认 2px 下这个场景**不降级**，这是正确的：相机距离 47.5u 时 L1 的 0.2094u 误差
在 1080p 下正好占 4.1 像素，超过预算。要在这里拿性能就把预算抬到 10~20
（实测 -17.5% / -40%），或者接受"近处不降级"。

### 5.3 远距离（验证自动选择链路）

`--cam-pos` / `--cam-look` 吃三个独立数值（不是逗号串）：

```bash
./build/GryceRenderSmoke.exe --api opengl --project test/demo_project \
  --cam-pos 0 120 320 --cam-look 0 10 0 --frames 12
```

`dist=272u` → 自动选 **L2**（阈值 97.9 / 212.4 / 384.3），不需要任何强制开关。

### 5.4 三后端一致性

`GRYCE_FORCE_LOD=3` 下三个后端都能正常降级（L0 → L3 的画面均值）：

| 后端 | L0 | L3 | L0 vs L3 像素平均 \|Δ\| |
|------|----|----|------------------------|
| OpenGL | 92.1 | 89.7 | 5.87 |
| Vulkan | 94.3 | 94.1 | 7.04 |
| D3D12 | 94.3 | 91.0 | — |

（后端名是 `--api opengl|vulkan|dx12`；写 `d3d12` 会被拒。）

## 6. 空间分块 LOD（单个巨模型）

### 6.1 为什么需要

**单个巨模型整屏时，逐物体 LOD 帮不上忙。** 主 demo 是一个 90u 宽的城市街区，
相机站在它边缘，任何"逐物体"判据（最近点 / 到球心 / 屏幕占比）都会得出
"该物体占满屏幕 → 用 L0"。这不是判据写错，是逐物体 LOD 的固有粒度：
近处立面需要 L0，远处街区本来可以用 L2，但一个物体只能有一个级别。

`assets/mesh_lod.h` 的 `ChunkedLod` 把它切成空间块：每块各自一条 LOD 链、
各自按自己的距离选级、各自绘制。

### 6.2 构建（`build_chunked_lod`）

1. 模型 AABB → `n³` 栅格，`n = choose_chunk_cells(tris)`，即 `cbrt(tris / 20000)`
   夹在 `[2, 6]`。
2. **三角形按质心整块归属**，不切开任何三角形 —— 切开会产生自造边界。
3. 每块重建紧凑网格（顶点按全局索引去重，块之间**共享同一批顶点位置**），
   再走一遍普通的 `build_lod_chain`。

**格数不是越多越好**（实测主 demo 1.46M 三角形、近距相机、16px 预算）：

| 每轴格数 | 块数 | 三角形/块 | 逐块合计三角形 | GPU 合计（4 轮取最小） |
|---|---|---|---|---|
| 2 | 8 | 20 万 | 1025k | 6.33ms |
| **3** | **20~21** | **2.3 万** | **802k** | **6.15ms** |
| 4 | 40~45 | 1.1 万 | 920k | 6.48ms |

原因是**格线越密、"钉住"的接缝顶点越多**（每个内部格面都要钉，且都是不可合并
的顶点），可简化量被吃掉。所以默认按"每块 ~2 万三角形"反推格数。

**裂缝**：相邻块共享的是"落在分块网格平面附近"的顶点。如果这些顶点在某一级
被合并掉，两侧就接不上（T 形接缝）。所以构建时把落在格线 `pin.eps` 带内的
顶点在所有级别**钉住**（簇代表 = 自己，用第 63 位做独占键），两侧都保留同一批
位置，接缝天然闭合。

`pin.eps = max(最长格边 × 2%, 对角线 × 1e-5)`。实测主 demo `eps=0.899`
只钉住 4.3% 的顶点，构建耗时与不钉持平。

> **踩过的坑**：加钉顶点后构建时间从 231ms 涨到 2579ms（10 倍）。不是"钉太多"
> （`GRYCE_CHUNK_PIN_STATS` 显示只有 4.3%），而是 `std::round` 是未内联的 libm
> 调用，被放在二分搜索内层反复调用。改成 `static_cast<int>(t + 0.5f)` 并把
> 钉住判定结果按输入网格缓存在 Scratch 里，开销归零（217ms vs 231ms）。

### 6.3 运行时：**只有在真省三角形时才接管**

每帧先算整模（逐物体）级别，再算每块级别，然后比三角形总数：

```
use_chunks = chunk_tris + 2% < whole_tris
```

- **远看**：整模早就能降到 L2/L3，分块反而"按块各降一级"总数更多，
  还要多付几十次绘制和每块 L0 的显存 → 一律整模画。
- **近看**（相机贴着/站在模型里）：整模判据只能选 L0，分块才能按远近有取有舍
  → 分块接管。

这个判据同时解决了"默认配置下白付成本"的问题：主 demo 默认 `lod_pixel_error=2`
时三块全部 L0，`chunk_tris == whole_tris`，于是**一次分块几何都不上传**，
显存与绘制批次与纯逐物体完全一致。

分块几何是**按需上传**的（`request_chunk_upload`，含 L0）。就绪判据是"每块至少有
一级可用"，而不是"每块的目标级别已就绪"：后者会让某块切级的那 1~2 帧整体退回整模
绘制，相机一动就闪一下 L0。目标级别还在上传时，`draw_mesh_handle_at` 逐块退到
**当前已就绪的最高级别** —— 画的是同一片几何、只是级别粗一点，既不重复绘制也不缺
几何。只有某块一级都没有时才退回整模一次绘制（一半分块 + 整模混画会把同一片几何
画两遍）。

> **踩过的坑**：`chunks_ready()` 要求"每块当前级别都已上传"，而 `update_lod`
> 里写着 `if (st.active > 0)` 才投递、`request_chunk_upload` 里 `level <= 0`
> 直接 return —— L0 块永远不上传，就绪判定恒假，分块从不接管（表现是"选级
> 直方图完全正确但画面与 L0 逐像素相同"）。

### 6.4 实测（主 demo，1080p，MSAA 4x，同会话交替 4 轮取最小值）

相机贴近模型（`--cam-pos 0 24 26 --cam-look 0 12 0`，模型中心 25.7u），16px 预算：

| 配置 | GPU 合计 | vs L0 |
|---|---|---|
| `GRYCE_NO_LOD=1`（恒 L0） | 7.25ms | — |
| 逐物体 LOD（`GRYCE_NO_CHUNK_LOD=1`） | 6.84ms | -5.7% |
| **分块 LOD（默认 3³）** | **6.17ms** | **-14.9%** |

分块比逐物体再快 **-9.8%**。同时画质更好：分块画面均值 87.0、L0 是 87.1、
2³ 分块是 86.8 —— 分块把三角形省在了远处，近处仍是 L0。

选级分布（3³）：sub0 `L0×9 L1×7 L2×4`、sub1 `L0×10 L1×6 L2×4`、
sub2 `L0×12 L1×6 L2×3`；逐块合计 231k + 291k + 280k = 802k，
整模判据分别只能给 469k / 309k / 446k（共 1224k）。

更低预算时整模胜出（分块没好处就不接管）：

| `lod_pixel_error` | 逐物体 GPU 合计 | 分块 GPU 合计 | 决策 |
|---|---|---|---|
| 4 | 7.51ms | 7.54ms | 部分子网格整模 |
| 8 | 7.57ms | 7.61ms | 同上 |

远看（默认相机，模型中心 47.5u）：2px 分块与逐物体同为 L0（8.5 vs 8.6ms，噪声内）；
40px 整模胜出（分块 ~150k 三角形 vs 整模 L3 59328），3.90 vs 4.09ms —— **没有回退**。

16px 的画面与 L0 的像素平均 \|Δ\| 只有 **0.816**（>8 差异 3.25%），
16px 预算下看不到细节损失。

**三后端一致**：同一机位 16px，GL / VK / DX12 的选级、逐块三角形数与接管决策
逐行相同（sub0 `L0×9 L1×7 L2×4` 231280 vs 整模 469451；sub1 291278 vs 308620；
sub2 `L0×12 L1×6 L2×3` 279904 vs 445717），画面均值 87.0 / 94.5 / 93.9 ——
差异只来自各后端的色调映射，LOD 决策与后端无关。

### 6.5 接缝验证

同一预算下对 `GRYCE_CHUNK_NO_PIN=1` 做 A/B，统计"L0 是模型、降级后变成天空"的
像素数（破洞代理指标）：钉住 = 1537 像素，不钉 = 2981 像素（**-48%**）。
扣掉轮廓正常收缩的那部分，钉顶点基本把接缝堵住了；画面里看不到格线状裂口。

### 6.6 成本

主 demo 三个子网格（1.46M 三角形）分块构建合计约 **0.96s**（一次性，
`build 308 + 327 + 329ms`，其中链生成占 ~60%），相对 92MB FBX 的导入时间
（~12s）不算大。3³ 比 2³ 还快一点（1.23s → 0.96s）：块更小、简化更快。
显存只在分块真正接管时才按需增加（等于被绘制块的几何），默认配置下为 0。

## 7. 已知边界

- 分块是**均匀立方栅格**，不按几何分布自适应。城市/地形这类"薄"模型在
  退化轴上靠 `min_cell = 对角线 × 1e-3` 兜底，可能切出空块（空块不生成）。
- 分块级别切换**没有过渡**：相邻块差两级时在边界能看到细节突变（没有
  geomorph / 交叉淡入）。目前靠"钉住边界顶点 + 8% 滞回"压住抖动。
- 逐块遮挡剔除只做了视锥剔除，没有 HZB 遮挡剔除 —— 背面块仍在画。
- 每块独立 LOD 链**不复用**跨块信息，总三角形数比理论最优多 10~20%
  （这就是"分块不一定赢"的根源，靠 6.3 的判据规避）。
- `min_triangles=512` 以下的块退化成只有 L0 的单级链（不丢，丢会留洞）。

## 8. 排查

| 现象 | 看什么 |
|------|--------|
| LOD 完全不生效 | `GRYCE_LOD_DEBUG=1`：`cam_dist` 是否被夹到很小（相机在包围球内）；`thresholds` 是否远大于实际距离 |
| 切级时轮廓跳一下 | `lod_pixel_error` 太小 / `lod_bias` 在滞回带外；或相邻级误差差得太多（把 `ratio_per_level` 调小） |
| 切换那两帧模型消失 | `draw_mesh_handle()` 回退逻辑被破坏（应回退到已就绪的最高级别，不是返回无效句柄） |
| 边缘闪烁 / 破洞 | 某个 pass 没用 `draw_mesh_handle()`（预通道 / 阴影 / 主 pass 三者必须一致） |
| 阴影比本体精细 / 粗糙 | 同上：阴影 pass 也用当前级别 |
| 小物体没 LOD | `min_triangles=512` 以下直接跳过（生成一条链不值得） |
| 分块选级直方图正确但画面等于 L0 | `chunks_ready()` 恒假：某块当前级别没上传（L0 也必须上传，见 6.3）。`GRYCE_LOD_DEBUG=1` 看 `ready=` 与 `uploads=` |
| 分块比逐物体还慢 | 看日志 `tris whole L?(N) vs chunked(M)`：分块只有在 M 明显小于 N 时才该接管（6.3 的判据） |
| chunk 边界有格线状裂口 | `GRYCE_CHUNK_NO_PIN=1` 对照；`pin.eps` 需覆盖跨格线三角形的顶点偏移 |
| 分块构建慢 | `GRYCE_CHUNK_PIN_STATS=1` 看钉住比例；构建日志里 `assemble / chain` 两段分开算 |
