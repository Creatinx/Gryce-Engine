# Gryce Engine 架构说明

> 本文档与当前源码保持一致，是模块边界、链接方向与工程组织的权威说明。
> 若某处与源码不符，以 `src/CMakeLists.txt` 与本文为准并更新本文。

## 一、模块布局

引擎核心按模块拆分为多个 DLL，通过**纯 C API**（`extern "C"`，命名如 `GCore_*`）对外服务。
上层 `GryceEngineUtils` 是面向引擎宿主（游戏 / 编辑器）的静态 C++ 包装层，只做薄封装，不重写核心逻辑。

| 模块 | 形态 | 职责 |
|---|---|---|
| `GryceCore` | DLL | ECS、Scene/Entity/组件、Math、UUID、Reflection、资源加载、动画、脚本（QuickJS）、渲染抽象层、音频组件的承载宿主 |
| `GryceRenderer` | DLL | 渲染管线（RenderPipeline、Shadow、后处理）、GL/Vulkan 后端、Mesh/Texture/Material、ImGui Backend |
| `GrycePlatform` | DLL | 窗口、输入、光标（GLFW） |
| `GrycePhysics` | DLL | 物理：Box2D（2D）+ Jolt（3D）、物理系统 |
| `GryceAudio` | 静态模块 | miniaudio 音频引擎（编译进 `GryceCore.dll`） |
| `GryceEngineUtils` | INTERFACE/STATIC 聚合 | 上层统一入口，`include/GryceEngineUtils/` 公开 C++ 头 |

`GryceCore` 中各 DLL 公共 C API 头分别位于 `src/GryceCore/`、`src/GryceRenderer/`、
`src/GrycePlatform/`、`src/GrycePhysics/`。

## 二、链接方向

```
GrycePhysics ──▶ GryceCore ──▶ GryceAudio(static)
GryceRenderer ─▶ GryceCore        │
GrycePlatform ─▶ GryceCore ◀──────┘
GryceEngineUtils ──▶ 各 DLL 的 C++ 包装
GryceEditor / GryceGame ──▶ GryceEngineUtils / 各 DLL
```

- 依赖方向**单向由 DLL 指向 `GryceCore`**，`GryceCore` 不反向依赖任何其他 DLL。
- `GryceAudio` 是 `GryceCore` 的静态模块：它只依赖 header-only 的 math，不反向引用 Core 符号，
  因此折叠进 `GryceCore.dll`，无 DLL 循环。
- 物理**类型头**与**实现**均归位到 `GrycePhysics`（含 `physics_system_{2d,3d}.h`），
  `GryceCore` 不再导出物理类型。

## 三、有意识地保留在 Core 的领域（暂不拆分）

为避免为拆而拆引入 DLL 循环或高耦合，以下领域保留在 `GryceCore`：

- **脚本**（`script/` + `ecs/systems/script_system`）：被 Core 内 ECS 系统强依赖，且 `src/ui`
  存在并行脚本运行时，拆分收益低、风险高。
- **渲染抽象层**（`render/rendering_device.h`、`storage_rd/*`、渲染管线）：`GryceRenderer`
  后端已依赖 Core，把抽象移出即成 DLL 循环。
- **资源加密格式**（gpack/pak/aes_gcm）：与 `resource_loader` / `asset_manager` 交织，拆开收益低。

`GryceAudio` 的独立 DLL 化被 `render_pipeline` 与 `audio_source` 组件对 `AudioEngine` 的直接调用
所阻塞；彻底解耦需改为 C API 服务门面（见 `src/CMakeLists.txt` 中 GryceAudio 的注释），作为后续事项。

## 四、对外接口

- **C API 是跨 DLL 与上层消费的唯一稳定通道**。新增供编辑器/工具使用的能力，应优先以
  C API（`*_api.h`）暴露，而非让上层直接 `#include` 内部头。
- 上层 `GryceEngineUtils`（`include/GryceEngineUtils/`）是 C++ 薄封装，按 `GRYCE_ENABLE_*`
  开关控制 ECS / 物理 / 音频 / 脚本 / UI 模块。

## 五、构建与产物

- 统一使用 `python build.py`（或 CMake 直连，二者共享配置与输出布局）。
- 构建产物统一组织为**自包含目录**：`build/<Config>/bin/<Config>/dist/<Target>/`，
  每目标含自身可执行文件与全部依赖 DLL，可直接拷贝分发；执行体命名与其父目录一致
  （如 `GryceEditor/GryceEditor.exe`、`GryceGC/GryceGC.exe`、`GryceGame/GryceGame.exe`）。
- 游戏入口 `GryceGame.exe` 由 `templates/GameTemplates.cpp` 生成，作为 GryceGC 打包产物运行。

## 六、资源与打包

- 每个资源文件打成一个独立的 `.gpkg` 包（GPAK v4，ChaCha20 流加密，12 字节 nonce）。
- `.gpkg` 文件名用随机 Base64URL 编码，不沿用逻辑命名；解密密钥以 `enc_key_hex` 存入项目根
  唯一配置 `project.data`（JSON，合并了清单与运行时设置）。
- 运行时加载：真实文件优先，包内提取兜底。
