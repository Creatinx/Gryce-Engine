# Gryce Engine — 架构说明

> 本文档描述 Gryce Engine 的模块划分、依赖关系、线程模型与关键数据流。功能实现状态见 [已实现功能](./已实现功能.md)，C API 细节见 [C API 调用文档](./C-API调用文档.md)。

---

## 1. 总体分层

```text
┌──────────────────────────────────────────────────────────────────┐
│  宿主层                                                          │
 │  · C++ 应用 — 直接链接引擎内部 C++ API │
│  · WPF 编辑器（editor/，C#）— 只通过模块 C API（P/Invoke）通信    │
└───────────────────────────────┬──────────────────────────────────┘
                                │ C ABI（extern "C"，cdecl，UTF-8 字符串）
┌───────────────────────────────▼──────────────────────────────────┐
│  模块层（4 个 DLL）                                               │
│  ┌───────────────┬───────────────────┬──────────────┬───────────┐ │
│  │ GryceCore.dll │ GryceRenderer.dll │ GrycePlatform │GrycePhysics│ │
│  │ ECS/Scene     │ OpenGL/Vulkan 后端│ .dll          │ .dll       │ │
│  │ Entity/Comp   │ RenderSystem2D/3D │ Window/Input  │ Jolt 3D    │ │
│  │ Reflection    │ ImGui Backend     │ Cursor/GL 上下文│ Box2D 2D │ │
│  │ Assets/Anim   │                   │              │ PhysicsSystem│
│  │ Audio/Math    │                   │              │             │
│  │ render 抽象   │                   │              │             │
│  └───────┬───────┴─────────┬─────────┴──────┬───────┴─────────────┘
└──────────┼─────────────────┼───────────────┼───────────────────────┘
           │                 │               │
           ▼                 ▼               ▼
       RenderContext   GLFW/GLEW      Jolt/Box2D（第三方）
       RenderThread
       RHI：Vulkan（默认）/ OpenGL（兼容）
```

## 2. 模块职责与依赖

### 2.1 模块边界

| DLL | 核心职责 | 公共头文件 |
|---|---|---|
| `GryceCore.dll` | `ecs::World`、Scene/Entity、组件与反射、资源（AssetManager/加载器）、骨骼动画、音频、数学、`res:/` 资源路径、**渲染抽象层**（RenderContext/Material/Mesh/Shader/Texture/Framebuffer/RenderPipeline/Render2D/FontAtlas/IBL/RenderThread）、命令队列、日志、QuickJS 脚本运行时、UI 系统 | `src/GryceCore/*.h` |
| `GryceRenderer.dll` | OpenGL 4.6 后端、Vulkan 1.2 后端、`Renderer2D` 实现、ImGui 渲染通道、`RenderSystem2D/3D` | `src/GryceRenderer/*.h` |
| `GrycePlatform.dll` | GLFW 窗口（含外部 HWND 注入）、`InputManager`、光标、GL 上下文归属 | `src/GrycePlatform/*.h` |
| `GrycePhysics.dll` | `IPhysicsWorld2D/3D` 抽象、Jolt/Box2D 后端、`PhysicsSystem2D/3D` | `src/GrycePhysics/*.h` |

> 注意：渲染的**抽象与管线**位于 GryceCore，**具体后端**位于 GryceRenderer——这是为打破「GryceCore 的 RenderSystem 依赖 Renderer」的循环依赖而做的边界划分。

### 2.2 依赖关系（CMake target）

```text
GryceCore      ← 无内部引擎依赖（基础层）
GrycePlatform  → GryceCore（共享类型、日志）
GryceRenderer  → GryceCore + GrycePlatform（窗口句柄）+ GLFW/GLEW/Vulkan
GrycePhysics   → GryceCore + Jolt/Box2D

examples_common → GryceCore + GryceRenderer + GrycePlatform + GrycePhysics
 3dtest / 2dDemo → examples_common
gryce_tests     → 全部 4 个 DLL + GTest
```

### 2.3 第三方依赖

- **源码随仓库**：imgui、imguizmo、nlohmann/json、stb（image/image_write/truetype）、miniaudio、tinyexr；
- **构建时自动下载**（`tools/deps_manager.py` → `build/deps/`，`deps_cache/` 缓存）：GLFW 3.4、GLEW 2.2.0、Assimp 5.4.3（可选）、Box2D 3.0.0、Jolt 5.2.0、GoogleTest 1.15.2；
- **条件编译宏**：`GRYCE_HAS_VULKAN`、`GRYCE_HAS_ASSIMP`、`GRYCE_HAS_NLOHMANN_JSON`、`GRYCE_HAS_BOX2D`、`GRYCE_HAS_JOLT`、`GRYCE_HAS_GLFW`、`GRYCE_HAS_GLEW`、`GRYCE_HAS_IMGUI`、`GRYCE_HAS_GTEST`。

## 3. 线程模型

### 3.1 编辑器（WPF）

```text
UI 线程（DispatcherTimer，60Hz）
  ├─ GCore_BeginFrame(dt) → 命令消费（≤30/帧）+ world.update（Play Mode）
  ├─ GCore_EndFrame()     → 日志转发 + 延迟回调
  └─ GInput_Inject* / GCore_PushCommand（WPF 事件 → 引擎）

渲染线程（GL 专用，垂直同步）
  ├─ GWindow_MakeContextCurrent()
  ├─ GViewport_SetSize() / GRender_BeginFrame()
  ├─ GRender_RenderWorld()（同步模式下补传网格，30/帧预算）
  └─ GRender_EndFrame() → 锁外 swap（避免 VSync 阻塞 UI 线程）

共享
  ├─ 全部导出 API 由全局递归互斥锁保护（GRYCE_API_GUARD）
  └─ 命令队列：UI 线程无锁写 front，Core 帧内 swap 读 back
```

### 3.2 独立游戏项目

单主循环驱动窗口/输入/更新/渲染；`RenderContext` 异步模式下内部启动渲染线程，主线程通过命令队列提交绘制；`render_ctx.start()` / `pause_render_thread()` / `resume_render_thread()` 控制其生命周期。

GryceGC-A 项目目录包含 `project.gproj` + `project_settings.json` + 分类资源目录，
可经 `grycegc` 打包为独立游戏（GryceGame 模板入口自动加载主场景）；标准说明见
[GryceGC-A](./GryceGC-A.md)。

## 4. 关键数据流

### 4.1 编辑操作（命令模式）

```text
Editor（Hierarchy/Inspector/Gizmo）
  → GCommand{ type, payload } → GCore_PushCommand / PushCommands
  → CommandBuffer（8192 × 2，双缓冲）
  → GCore_BeginFrame：swap + 消费（30/帧，溢出回队）
  → process_command：LOAD_SCENE / CREATE_ENTITY / SET_PROPERTY / PLAY_MODE ...
  → ecs::World / scene::Entity / Reflection 写入
  → GCore_EndFrame：OnEntityListChanged / OnSceneLoaded 回调
  → 编辑器刷新面板
```

### 4.2 渲染数据流

```text
Scene（MeshRenderer/SkinnedMeshRenderer + Transform）
  → RenderSystem3D / upload_pending_meshes（同步模式，预算 30/帧）
  → AssetManager 加载 mesh/texture
  → RenderPipeline（PBR + 阴影 + IBL + HDR/Bloom/Tonemap）
  → RenderContext 命令队列
  → IRenderBackend（OpenGL / Vulkan）
  → 交换链 → HWND（编辑器）/ GLFW 窗口（demo）
```

### 4.3 Play Mode

```text
ECMD_PLAY_MODE
  → 序列化当前场景为 JSON 快照
  → world.set_updates_enabled(true)
  → AnimatorSystem / FractureSystem / PhysicsSystem（Jolt/Box2D）每帧驱动

ECMD_STOP_MODE
  → 反序列化快照 → attach_scene 替换场景（播放期改动全部丢弃）
  → world.set_updates_enabled(false)
```

## 5. 目录布局要点

```text
src/
├── CMakeLists.txt        # 4 个 DLL target + 编辑器 DLL 自动部署规则
├── api/                  # C API 实现（.cpp）
├── GryceCore/            # 公共头（对外发布）
├── GryceRenderer/        # 公共头
├── GrycePlatform/        # 公共头
├── GrycePhysics/         # 公共头
├── ecs/                  # ECS 系统（动画/碎裂在 Core，物理在 Physics，渲染在 Renderer）
├── render/ opengl/ vulkan/  # 渲染核心 + 后端
├── ui/                   # UI 系统（控件库、布局、渲染、QuickJS、数据绑定、热重载）
├── script/               # QuickJS 脚本运行时（GryceSRT：ScriptVM/绑定/工具）
└── server/               # 网络服务（预留）

editor/                   # WPF 编辑器构建产物（Native DLL 自动部署）
```

> 约定：任何手动复制到编辑器输出目录的原生 DLL，都必须同步在 `src/CMakeLists.txt` 中登记自动复制规则（`gryce_copy_dll_to_editor`）。
